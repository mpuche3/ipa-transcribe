The Turing Machine.
Before anyone had built a working computer, there was a question that needed an answer. What does it actually mean for a task to have a method? People spoke of following rules, of doing something mechanically, of calculating, but nobody could say precisely where the line fell between a real method and a vague hope. The idea of the Turing machine was invented to draw that line.
The machine itself is almost nothing. Picture an endless strip of tape divided into squares, each square holding a single symbol. A reading head sits over one square at a time. It can look at the symbol beneath it, wipe it away and write a different one, and move one square left or right. Inside, the machine has a small set of states, like positions in a short list. Its whole behavior is fixed by a table: for each combination of current state and symbol seen, the table says what to write, which way to move, and which state to go to next. That is the entire design. No arithmetic is built into it, there is no memory beyond the tape, and no cleverness of any kind is involved.
The point of such a bare device is not engineering. It is definition. Anything a person can do by following a fixed set of rules, without needing insight or luck along the way, can also be done by a machine of this kind. Give the machine the right table and enough tape, and it will grind through the steps. So the claim that there is a method for something, and the claim that a machine of this kind could do it, turn out to mean the same thing. That equivalence is the whole idea, and everything else follows from it.
This matters because it makes a slippery question answerable. If two people disagree about whether some task is mechanical, we no longer have to trade intuitions. We can ask whether such a machine could do it. The answer is about what is possible at all, not about how fast, how cheap, or out of what materials. Speed is a separate subject, and so is cleverness in design.
The deepest consequence is that one machine can do the work of every machine. The table that defines a machine is itself just a pattern of symbols, and symbols can be written on tape. So a single machine can be handed a description of any other machine, read it, and then behave exactly as that machine would. One fixed device, endlessly many behaviors. This is why the notion of software makes sense at all, and why a single piece of hardware can run a game in the evening and a tax return in the morning. Before this idea, a machine was a purpose. After it, a machine can be general.
The same reasoning that gives the machine its reach also puts a wall around it, and this is where honesty is required. There are questions the machine can never answer, and the obstacle is not speed or size or cleverness. It is the shape of the questions themselves.
The clearest case is this. Hand the machine a description of a machine together with its starting tape, and ask whether that described machine will ever stop. This is a perfectly definite question with a definite answer. Yet no method can settle it in every case. Suppose there were one. Then you could build a machine that takes its own description, asks what the method says about it, and then does the opposite, running forever if the answer says it stops and stopping if the answer says it runs forever. Whatever the method replies about this machine, the machine does the reverse, so the reply is wrong. Since a method that is wrong about some case is not a method, none exists. The gap is not waiting to be filled by better engineering. It can never be filled.
The consequences reach further than one awkward question. No method can take an arbitrary mathematical statement and decide whether it can be proved. Any such method fails on cases that are definite and meaningful, and no amount of refinement repairs it.
Nor is the wall a small corner of the landscape. The tasks a machine can carry out form a special and carefully built subset of all the questions you can pose. Most of what can be written down as a definite question has no method behind it. That is a permanent fact about the world of rules, not a temporary shortcoming.
The machine also separates two things that people usually mix together: what can be done, and what can be done soon. Some tasks are perfectly mechanical and still hopeless in practice, because the number of steps grows so fast that no amount of hardware keeps up. Knowing that a method exists tells you nothing about whether it is usable. Practical computing lives in that gap, and the gap does not close merely because machines get faster.
The idea also frames a question it can never itself answer. If thinking is at bottom the carrying out of fixed steps on symbols, then a machine of this kind could in principle think, however enormous the table and the tape would have to become. If thinking depends on something that fixed steps can never capture, then no machine of this kind ever will. The idea does not settle which of those is true, but it makes the disagreement precise, which is more than anyone had managed before. It is often quoted as proof on both sides, and on both sides it is being misread.
Because the machine is a definition rather than a device, it never becomes obsolete. Every computer built since is an instance of it, whatever its parts and whatever its speed. When someone says that a new machine can compute something, the claim is not really about the new machine. It is a claim about what fixed rules can do, and that was settled long before the hardware existed.
The lasting value of the idea is that it turned a cloudy question into a sharp one, and the sharp version came with a limit built into it. A machine that nobody ever needed to build remains the clearest description we have of what it means to follow a rule.
